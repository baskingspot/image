# TIFF decode stage 2 (JPEG) against libtiff, 2026-11-02

`image.tiff.Decoder` with JPEG compression (wave 3, stage 2) against
libtiff 4.7.2 with libjpeg-turbo 3.2.0, the bar, and the comparison arms
Rust's `tiff` crate (through `image` 0.25.9) and Go's
`golang.org/x/image/tiff`. Every arm decodes a whole file from memory per
call into RGBA8 (bench/ops.tsv); ours with a `Seeker.fixed` over the input.
Throughput is megapixels per second; a ratio is this package's throughput
over the arm's (above 1, ours is faster), the geometric mean over rows of
each row's median paired ratio over 10 rounds. The other TIFF rows are
measured again in the same run: stage 1's code, on main b08d00f (since
then main has moved the `compress` pin, which the Deflate rows use).

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512; a shared cloud
host, so only paired ratios are steady), Linux 6.1, Zig 0.16.0 ReleaseFast
for this CPU; C arms `cc -O3 -march=native`, Rust `target-cpu=native`, Go
`GOAMD64=v3`. Command: `just bench-compare 10 tiff-decode-none
tiff-decode-lzw tiff-decode-deflate tiff-decode-packbits tiff-decode-jpeg
tiff-decode-g4` (exit 0). Raw output in `tiff-stage2-20261102/`:
`summary.txt` (the table bench-compare prints), `benchstat.txt`,
`check.txt`, `raw-*.txt`, `config.txt`, and `rss.txt` (peak RSS by size
class).

Inputs, `bench/corpus-gen/tiff/jpeg/` (bench/corpus/tiff.sh, checksums in
bench/corpus/tiff.sha256): every shared source, from 16×16 icons to the
50-megapixel mosaic, as 8-bit RGB that libtiff's `tiffcp -c jpeg` rewrites
as YCbCr 2×2 at quality 75, in strips of libtiff's default 8 KiB rounded up
to a multiple of 16 rows, with the tables in JPEGTables (44 files). The
row is `own`, since the arms need not use libjpeg-turbo's upsampling, but
ours checksums the same as libtiff's on every input. The `tiff` crate fails
every input (it decodes gray and RGB JPEG data, not YCbCr), and Go's
package has no JPEG, so libtiff is the only arm on this row.

JPEG beats libtiff at every size: 6.5× on icons, where libtiff's per-file
setup (TIFFClientOpen, the directory, libjpeg's decompressor and its
JPEGTables pass) dominates, and 1.1–1.3× past them, which is
`image.jpeg`'s speed against libjpeg-turbo's (decoding straight into the
caller's RGBA8 rows, where libtiff's caller reads RGB strips and expands
them). The mosaic, whose strips are 16 rows of 8192 pixels, is the one row
near parity (0.96).

Deflate is faster than in stage 1 (0.67 and 0.71 of libtiff past icons,
from 0.53 and 0.57), with no change in this package: the `compress` pin
is newer. LZW, PackBits, and G4 are where stage 1 left them, about half
libtiff's speed past icon size; decision 23 makes that the follow-up after
this stage.

A JPEG page's work memory is its offsets and counts, a 4 KiB staging
buffer, JPEGTables, and `image.jpeg`'s work for one strip's frame
(`jpeg.Decoder.workLen`, single scan): 33 KiB for a 16×16 icon, mostly
its Huffman tables, 90 KiB for a 768×512 photo, and 651 KiB for the
mosaic's 8192-wide strips. The YCbCr strips decode straight into the
caller's rows, so nothing else is held; libtiff holds a strip of RGB on
top of libjpeg's own buffers.
