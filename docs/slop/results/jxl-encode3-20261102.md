# JPEG XL lossless encode, stage 3, 2026-11-02

Stage 3 of `image.jxl.encode` (`wave5-jxl-encode3`). Stage 2 is
`jxl-encode2-20261102.md`, and its method (corpus totals through a
scratch program, and A/Bs through `convert-tails-20261102/ab.sh`) is
used here unchanged. docs/slop/jxl-encode.md has the design.

| commit | change                                                         |
| ------ | -------------------------------------------------------------- |
| leaves | default's tree may grow to 1024 leaves (was 2048), decision 71 |
| local  | groups take palettes and color transforms of their own         |

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512; a shared cloud
host, so only paired ratios are steady), Linux 6.1, Zig 0.16.0 ReleaseFast
for this CPU; libjxl 0.12.0, `cc -O3 -march=native`, one thread.

## Leaves: 1024 at default

The owner chose 1024 leaves for `default` over stage 2's 2048 (decision
71), trading 0.15% of size for time. Corpus totals, two runs of each
build interleaved on core 3 (`jxl-encode3-20261102/leaves/corpus.txt`):

## Local transforms: screenshots

After stage 2, default was 3.3% and 7.1% larger than cjxl e7 on the
amazon.com and apple.com screenshots, and 7.1% on the dice photo. One
transform served the whole image: a palette when the image had at most
1024 colors, else one RCT. Most of these images' 256×256 groups have
few colors: 43 of amazon's 144 groups, 70 of apple's 114, and 97 of
cnn's 126 have at most 1024 (`screenshot_*` in the corpus).

cjxl tells what it gets from per-group transforms (`cjxl -d 0 -e 7
--num_threads=0` on apple.com, `jxl-encode3-20261102/local/cjxl.txt`):

| cjxl e7 option                         | apple.com bytes |
| -------------------------------------- | --------------- |
| (none)                                 | 1,107,864       |
| `--patches=0`                          | 1,107,864       |
| `--modular_palette_colors=0`           | 1,136,121       |
| `-Y 0` (no local channel palette)      | 1,107,636       |
| `-C 13`, the best of the 42 fixed RCTs | 1,117,729       |

So local palettes are worth 2.5% to it there and per-group RCTs 0.9%;
patches nothing. Each stream may declare transforms in its header
(18181-1, the Modular sub-bitstream's transforms), and the global tree
codes the result.

Now, when the image has several groups and no palette of its own, each
group declares a palette of its colors or an RCT. Corpus runs at default
on the files the change moves (13 files, 9,424,188 bytes before;
`local/subset.txt`):

| rule                                                     | bytes                |
| -------------------------------------------------------- | -------------------- |
| before (one transform for the image)                     | 9,424,188            |
| every group that can take a palette does; others own RCT | 9,262,989            |
| palettes as above; others the image's RCT                | 9,282,660            |
| no palettes; every group its own RCT                     | 9,401,966            |
| by estimate: palette if cheaper, own RCT if 3% cheaper   | 9,263,358            |
| estimate, own RCT at any gain                            | 9,272,022            |
| estimate, and a palette at most 8 colors                 | 9,250,504            |
| that, and all palettes when 70% of groups can take one   | **9,211,979**        |
| that, own RCT at 1%                                      | 9,251,703            |
| that, own RCT at 10%                                     | 9,242,303            |
| that, no own RCTs                                        | 9,241,816            |
| that, all palettes at 50%                                | 9,242,737            |
| estimate with five gradient contexts                     | 9,286,610            |
| estimate, palette samples at 3 or 8 bits (was 5)         | 9,271,648; 9,283,946 |

The kept rule (`local` in encode.zig): a group takes an RCT of its own
when its estimate is 3% under the image's; it takes a palette when the
palette's indices plus 5 bits a palette sample are estimated under its
channels, when it has at most 8 colors, or when 70% of the groups can
take a palette at all. The estimate is stage 1's (order-0 entropy of
clamped-gradient residuals on row segments, now with alpha and the
palette indices beside the 15 RCT channels), and it undervalues palettes
on text: cnn.com's groups of about 217 colors were estimated 2–76% dearer (at fast)
as palettes, yet taking them all saves 3% of the file. A shared tree
explains the margin: groups whose channels mean different things fit it
worse, so a group RCT that wins by a hair loses in the file (icon_512
address_book still loses 4.4%, the one file that does).
