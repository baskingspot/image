# PNG decode performance pass, 2026-11-02

PNG decode ran 0.79× Wuffs (icons 0.76, above 1 MP 0.87) with compress at
fd03d72 (`png-20261101.md`). Profiles of `bench-image` (perf, the 52 files
of `bench/corpus-gen/png/`) put the time in inflate (75–90% on photos), in
unfiltering (half of `test-dice-800x600`, a third of the 50 MP mosaic, both
nearly all Paeth rows), and on icons in the zlib header and Huffman table
build, the CRC, and per-row setup. The changes below are measured one at a
time, each against the build before it.

Inflate is compress's: its branch `image-perf-inflate` decodes whole
symbols from packed table entries and moves the PNG decode most
(compress's `docs/slop/results/flate-packed-entries-20261102.md`). Every
A/B here ran with this repository's `build.zig.zon` pointing at a checkout
of that branch, every arm alike; the code compiles and passes against
fd03d72 too, and the pin moves when that branch merges.

## Method

`ab.sh` from `convert-tails-20261102/` (the convert-rounding harness with
the operations, rows, and core from the environment): `png-decode` (whole
file to RGBA8) over the 52 files, the arms interleaved, 8 rounds pinned to
one core (`CORE=2`, or 3 for the palette run), 50 ms a sample, with
benchstat and peak RSS. Every run's checksums match every arm's, Wuffs's
included: the output is bit-identical. Each directory below holds the
run's `summary.txt` (this change against the build before it and Wuffs),
`summary-before.txt` (the build before against Wuffs), `rows.txt`,
`benchstat.txt`, `rss.txt`, `checksums.txt`, and the benchstat inputs.

CPU: Intel Xeon Processor @ 2.60GHz (3.3 GHz under load), 4 vCPUs,
AVX-512, a shared cloud host; Linux 6.1, Zig 0.16.0, ReleaseFast for this
CPU, Wuffs with `cc -O3 -march=native`.

Size classes as in `png-20261101.md`: icons (17 rows, to 64×64 and the
16-pixel-wide plant), to 1 MP (27), above 1 MP (8).

## Rows from the inflate window, whole rows converted (`window/`)

`pixels` read each row out of the inflate window into a row buffer
(`readSliceAll`) and unfiltered it there. Now `filter.unfilter` takes a
source apart from its destination, and a row up to 32 KiB (half the
window, which holds that much contiguously however it has slid) is
unfiltered straight from the window (`peek`, then `toss`): one copy of
every row fewer. Longer rows keep the old path. `Out.put` converts a row
in one call instead of 256-pixel spans when the samples need no expanding,
since each call has a fixed cost.

| class  | image MP/s | vs before | vs Wuffs |
| ------ | ---------- | --------- | -------- |
| icons  | 75.3       | 1.00      | 0.96     |
| ≤ 1 MP | 136.5      | 1.02      | 0.93     |
| > 1 MP | 118.5      | 1.01      | 0.97     |
| all    | 110.0      | 1.01      | 0.95     |

The `before` arm here is the conversion change of
`convert-tails-20261102.md` and the compress branch on main 8e7e4c8; this
run also timed main itself (`base`): `before` was 1.30× it (icons 1.38,
≤ 1 MP 1.25, > 1 MP 1.34), 0.94× Wuffs.

## Memory

Peak RSS of the benchmark process is 239.5 MiB for every build here
against Wuffs's 384.3 MiB (`*/rss.txt`); the decoder's work memory is
unchanged (72 KiB and two rows): the paired rows reuse the row buffers.
