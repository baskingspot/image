# JPEG XL lossless encode, stage 5, 2026-11-03

Stage 5 of `image.jxl.encode` (`wave5-jxl-encode5`): the JPEG XL orb made
`modular.pixelProps` and `modular.walk` pub (its speed branch, on main
since f2721b1), and the encoder was to use them in place of its own
copies. Method as in `jxl-encode4-20261103.md`.

| commit | change                                                  |
| ------ | ------------------------------------------------------- |
| props  | the encoder uses the decoder's `pixelProps`; same files |

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512; a shared cloud
host, so only paired ratios are steady), Linux 6.1, Zig 0.16.0 ReleaseFast
for this CPU; libjxl 0.12.0, `cc -O3 -march=native`, one thread.

## pixelProps: kept

The encoder's `pixelProps` was the same function as the decoder's, line
for line (properties 2 to 14 from a pixel's neighbours, carrying property
9 from the pixel before). It is gone; sampling and tokenizing call
`modular.pixelProps`. Every corpus file is byte for byte the same at
every effort (md5), and so is every bench row.

A/B (`props/summary.txt`), this build over main's, 5 rounds on core 3:
icons, ≤1 MP, and >1 MP all 1.00 at fast (e3 rows), and 0.99, 1.00, 1.00
at default (e7 rows); 84 of 86 rows within noise. Peak RSS is the same.

## walk: measured, not kept

`modular.walk` walks the decoder's tree two levels a step, as the
encoder's `Flat` does. Using it meant copying the encoder's tree into the
decoder's `Node`s (`decoderNodes`, smaller entries than `Flat`'s)
and walking those. The files were the same (0 of 86 bench rows
differ), but tokenizing was slower (`walk/summary.txt`, that build over
main's, 5 rounds on core 3):

| effort            | icons | ≤1 MP | >1 MP |
| ----------------- | ----- | ----- | ----- |
| fast (e3 rows)    | 0.99  | 0.96  | 0.91  |
| default (e7 rows) | 1.00  | 0.98  | 0.96  |

The slowest rows were apple.com (0.73 at fast, 0.92 at default) and the
512×512 icons (0.83 at fast). Per step `walk` loads both children,
tests whether each is a leaf, and clamps the property index, where
`Flat` has its children's properties, values, and the four grandchildren
precomputed in one entry; the decoder needs `walk`'s form
because its tree comes from the file and it cannot spend a pass on it.
Fast's tokenizing is a larger share of its time than default's, so it
loses more. The patch is `walk/walk.patch`.
