# JPEG CMYK through `cmyk8` and `image.convert`, 2026-11-02

Plan.md decision 15 added the `cmyk8` and `cmyk16` pixel formats and
`image.convert`'s SIMD kernel from `cmyk8` to RGB. `image.jpeg.Decoder` now
reports `cmyk8` (`cmyk16` past 8 bits) as native with `Options.cmyk = .raw`,
and its default 8-bit CMYK and YCCK path interleaves the inks into a
`cmyk8` row (`sample.inks`, 16 pixels at a time, YCCK's YCbCr converted
and inverted in the same pass) and converts that with the kernel, where it
had converted each pixel in a scalar loop. Past 8 bits the conversion stays
at the image's precision, as libjpeg-turbo rounds it. docs/slop/jpeg.md has
the design.

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512, a shared cloud
host whose rows swing by ±10% between rounds), Linux 6.1, Zig 0.16.0
ReleaseFast for this CPU. Inputs: `bench/corpus-gen/jpeg/cmyk`, 44 YCCK
files (Adobe transform 2, as Photoshop writes CMYK) that libjpeg-turbo
3.2.0's tjbench writes from the stage 1 sources at quality 85, black and luma
at full resolution and chroma at half (bench/corpus/jpeg.sh). Neither
tjbench nor ImageMagick writes untransformed CMYK, so those files come only
from the fuzz generator, which the oracle checks.

Output is unchanged: identical to djpeg's naive RGB on the 44 bench files
and an ImageMagick 4:4:4 YCCK file at full scale and, for 15 of them, at
1/2, 1/4, and 1/8; a unit test decodes flat CMYK and YCCK blocks to values
derived by hand, as inks and as RGB. Work memory grows by four bytes per
output pixel of one row for an 8-bit CMYK or YCCK image decoded to RGB (32
KiB at 8192 pixels wide), the `cmyk8` row; nothing else changes.

## Against the arms

`just bench-compare 10 jpeg-decode-cmyk` after the change. Every arm decodes
a whole file from memory per call to RGB8. The libjpeg-turbo arm decodes to
its inks a row at a time and converts them as djpeg does, in the same loop
(bench/c/libjpeg-turbo-jpeg.c); libjpeg-turbo and Wuffs checksum the same as
this package on all 44 rows. stb_image, Rust's `jpeg-decoder` (through
`image`), zune-jpeg, and Go convert CMYK their own ways and differ on every
row, so the operation is `own`. A ratio is this package's throughput over
the arm's, the geometric mean over rows of each row's median paired ratio
over 10 rounds:

| class (rows)  | image MP/s | vs libjpeg-turbo | vs Wuffs | vs stb | vs `jpeg-decoder` | vs zune | vs Go |
| ------------- | ---------- | ---------------- | -------- | ------ | ----------------- | ------- | ----- |
| icons (13)    | 84.1       | 3.68             | 1.45     | 1.46   | 1.87              | 1.41    | 5.34  |
| to 1 MP (23)  | 190.9      | 1.37             | 1.95     | 1.75   | 1.00              | 0.98    | 10.08 |
| over 1 MP (8) | 181.7      | 1.21             | 1.98     | 1.96   | 0.93              | 0.91    | 9.38  |

Above icon sizes zune-jpeg and `jpeg-decoder` run within 10% of this
package, ahead on the largest images, with their own conversions.
