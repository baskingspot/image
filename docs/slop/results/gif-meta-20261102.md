# GIF decode: ICC and XMP blobs, 2026-11-02

Decision 13 lets GIF report ICC profiles and XMP packets as blobs, which
needs each blob's offset in the input. The decoder now counts the bytes it
reads in `take`, `takeByte`, `readSlice`, and `skipSubBlocks`. The LZW
data's sub-blocks come through `takeByte` and `readSlice`, so this adds
one 64-bit add per sub-block of up to 255 bytes, plus one per extension or
header field. This checks that nothing got slower.

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512, shared cloud
host), Linux 6.1, Zig 0.16.0 ReleaseFast for this CPU, pinned to core 3.
A is bench-image at origin/main 57e228d, B the same with this change, on
the 52 rows of `gif-decode` and `gif-decode-anim`.

## Interleaved A/B

Both binaries serve the same row back to back, alternating which goes
first, 5 rounds of about 40 ms each per row; a ratio is B's throughput over
A's, the geometric mean over rows of each row's median (`ab.txt`; classes
split at 4,096 and 1,000,000 pixels):

| rows        | count | B / A |
| ----------- | ----- | ----- |
| still icon  | 14    | 1.003 |
| still 1mp   | 22    | 1.015 |
| still large | 10    | 0.982 |
| anim icon   | 2     | 0.988 |
| anim 1mp    | 3     | 0.998 |
| anim large  | 1     | 1.031 |
| all         | 52    | 1.003 |

No class moves beyond noise.

## Throughput

One `bench` pass of each binary (`BENCHTIME_MS=100`, sequential, so only
indicative: the classes swing up to 20% either way between passes;
`bench-A.txt`, `bench-B.txt`), geometric mean MP/s by class:

| class       | A     | B     |
| ----------- | ----- | ----- |
| still icon  | 415.3 | 384.5 |
| still 1mp   | 872.1 | 838.1 |
| still large | 589.4 | 637.8 |
| anim icon   | 90.8  | 98.1  |
| anim 1mp    | 218.7 | 248.3 |
| anim large  | 665.5 | 535.5 |

Memory: the work memory is unchanged. The decoder's state grows by the
`u64` count and a second `Metadata` for blobs after the first frame;
`readXmp` holds back the trailer in a 514-byte stack buffer and `readIcc`
reads into a 255-byte one.
