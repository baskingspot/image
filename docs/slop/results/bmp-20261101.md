# BMP and ICO decode and encode, 2026-11-01

`image.bmp` and `image.ico` against Wuffs (the bar for BMP decode), stb_image
and stb_image_write, Rust's `image` 0.25.9, `zune-bmp` 0.5.2, and Go's
`golang.org/x/image/bmp`, with `just bench-compare 10 bmp-decode
bmp-decode-rle bmp-decode-bgra bmp-encode-rgb bmp-encode-rgba bmp-encode-gray
ico-decode` on the branch rebased onto `0d5385a`. Throughput is megapixels per
second; a ratio is this package's throughput over the arm's (above 1, ours is
faster), the geometric mean over rows of each row's median paired ratio over
10 rounds.

Machine: Intel Xeon Processor @ 2.60GHz (4 vCPUs, AVX-512; a shared cloud
host), Linux 6.1, Zig 0.16.0 ReleaseFast for this CPU; C arms `cc -O3
-march=native`, Rust `target-cpu=native`, Go `GOAMD64=v3`. Input at a page
boundary, output 2048 bytes past one, 50 ms samples. Raw output in
`bmp-20261101/compare/` (`config.txt`, `rss.txt`, `benchstat.txt`,
`summary.txt`, `rows.txt`, every sample in `raw-<arm>.txt`), the per-size
peak RSS in `bmp-20261101/rss-by-size.txt`, and the two A/Bs below in
`bmp-20261101/ab-palette/` and `bmp-20261101/ab-encode/`.

Inputs: `bench/corpus/bmp.sh` writes every source as 24-bit (BMP3), 32-bit
with alpha (a BITMAPV5HEADER with bitfields), and 8-bit with a 256-color
table, and the non-photos as RLE8, with ImageMagick: 132 uncompressed and 35
RLE8 files, 16×16 icons to the 50-megapixel mosaic. `ico.sh` writes the 16,
32, and 64 pixel icons and 256-pixel ones as one-entry 32-bit ICOs. Encode
reads `raw/{rgb8,rgba8,gray8}` squares, 16×16 to 4096×4096. Classes: icons
are at most 64×64, "1mp" up to a megapixel, "large" above.

Every arm's decode output hashes the same as ours on every row it has
(`same` operations). Encode outputs may differ (`own`): stb_image_write and
Go choose other headers and bit depths (stb writes gray as 24-bit), and
differ on all 15 and 10 of their rows; `image` writes the same bytes as ours
on all 15.

**Against Wuffs.** Icons are 1.30× (RGBA) and 1.45× (BGRA): no decoder
state to initialize, and the color table read in bulk (below). RLE is 1.3 to
2.6× in every class. Uncompressed rows from 1 megapixel up are at parity
overall (0.97 to 1.02), with 32 of 69 mid-size RGBA rows below 1. The
slowest rows are 24- and 32-bit images converted a row at a time:
`24-textures_plants-plant_01-166x1022` (0.69 in the run before this one),
`24-pngimg-academy_awards_PNG9-447x1192` (0.77 to 0.89), and the
1276-wide Wikipedia photos (0.78 to 0.85). A microbenchmark of
`image.convert.Converter` on that 166 by 1022 image shows why: BGR to RGBA
takes 51 µs a row at a time and 26 µs in one call, so the kernel's tail
costs about 25 ns per call, which is half of a 166-pixel row. That is in
`src/convert.zig`, which this branch does not own; the decoder already
converts each row in one call.

**Others.** stb_image, `image`, `zune-bmp`, and Go are 6 to 15× slower at
decode everywhere. `zune-bmp` has no RLE row: it rejects 8 of the 35 RLE8
inputs that Wuffs, `image`, and this package decode alike. At encode, gray
from 1 megapixel up is at parity with `image` and Go (0.97 to 1.28; all
three write the rows as they are, so this is memory bandwidth), and every
other encode row is 3 to 30× faster than the arms.

## Peak RSS

The decoders allocate nothing, so ours is the input and output buffers the
harness holds for every arm, plus the binary. One pass over each operation's
inputs, MiB:

| bmp-decode      | 385.9 | 386.8 | 609.0 | 386.7    | 386.6 | 1716.3 |

| bmp-encode-rgb  | 114.0 | -     | 114.5 | 114.8    | -     | -      |

By size, one call each (`rss-by-size.txt`): a 16×16 or 64×64 decode is 2.0
MiB for us against 2.9 for Wuffs (its decoder struct) and 2.4 to 2.9 for the
rest; a 768×512 decode 4.6 against 5.5 to 6.6 (Go 9.8); the 50-megapixel
decode 386.0 against Wuffs's 386.9, stb's 578 (its own pixel copy), and
Go's 772. Encode is 2.0 MiB at 16×16 for us against 2.5 to 2.9, and equal to
the buffers at 4096×4096 except Go (+65 MiB for RGBA).

## Changes measured: the color table in bulk, and encode writes

Interleaved A/B, `bench-image serve` pinned to the last core, 10 rounds
alternating which build runs first, benchstat.

- **The color table read in bulk** (`dib.readPalette`): one `take` per
  buffer's worth of entries with a SIMD alpha fill, instead of a `take` per
  entry. 8-bit decode to RGBA, 16×16: 958 → 417 ns (−56%, 267 → 614 MP/s);
  32×32 −40%; 64×64 −21%; rows above 128×128 unchanged; geomean over the 44
  8-bit rows −14.5% (BGRA −14.8%, 16×16 899 → 369 ns). Memory unchanged:
  the table was already on the stack.
- **Encode writes rows and the table whole** (`bmp.encode`): a row already
  in the file's format is written straight from the source, the 8-bit color
  table in one write, and the color hash table is only cleared for color
  sources. Gray encode, 16×16: 1029 → 268 ns (−74%); 64×64 −68%; 256×256
  −40%; 1024×1024 −8%; geomean −46%. 24- and 32-bit encode unchanged
  (−2%, within noise). Before it, gray encode was 0.72× `image` on icons and
  0.70× at 1 megapixel; after, 2.66× and 1.06×.
