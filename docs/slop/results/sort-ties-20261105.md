# Sort ties by index, 2026-11-05

Decision 79 (`docs/slop/plan.md`): the WebP lossless entropy-image tile
sort (`src/webp/encode_entropy.zig`) and GIF's octree merge sort break equal
keys by index, and GIF's median-cut box sort is stable (`std.sort.block`), so
equal keys keep their order in the list. Before, all three were
`std.sort.pdq` with the key alone, so equal keys came out in whatever order
pdq left them, and Zig 0.17's reworked pdq moved WebP and GIF bytes.

Sizes from `bench-image check` (len per input) on origin/main cf11e9f
(before) and the `sort-ties` branch (after), Zig 0.16.0, ReleaseFast,
native, on an Intel Xeon @ 2.60 GHz (Ice Lake). The GIF rows use the default
quantizer, Wu's, which sorts nothing; the last two rows are the same rows
rebuilt with `quantizer = .median_cut` (still) and `.octree` (animation),
a scratch change not committed.
